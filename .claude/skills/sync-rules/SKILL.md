# 音声同期ルール

音声とテロップのタイミングずれを検出・修正するためのルールです。

## ⚠️ 重要: FPS設定

**FPSは必ず `.claude/settings.json` から取得すること。**

```json
// .claude/settings.json
{
  "project": {
    "fps": 25  // ← この値を使用
  }
}
```

## 対象ファイル
- `src/Subtitles/subtitleData.ts` - 現在のテロップデータ
- 元のSRTファイル - 音声認識から生成されたタイムスタンプ（正解データ）

---

## 🔍 診断項目

### A. SRTとのタイミング比較

SRTファイルのタイムスタンプが「正解」です。
subtitleData.ts のタイミングがSRTとずれていれば、それが音声同期のずれ。

```typescript
// settings.json から fps を取得
const fps = 25;

// SRTの元データ
00:00:05,000 --> 00:00:08,500
こんにちは

// subtitleData.ts（フレーム換算: 5秒=125フレーム, 8.5秒=212フレーム @25fps）
{ startFrame: 125, endFrame: 212, text: "こんにちは" }  // ✅ OK

{ startFrame: 150, endFrame: 237, text: "こんにちは" }  // ❌ 1秒ずれ
```

### B. ずれの許容範囲

| ずれ | 判定 | 対応 |
|------|------|------|
| 0〜3フレーム（0.1秒） | ✅ 許容 | 無視 |
| 4〜15フレーム（0.5秒） | ⚠️ 軽微 | 報告、確認後修正 |
| 16フレーム以上 | ❌ 要修正 | 報告、慎重に修正 |

### C. ずれの種類

1. **全体的なずれ** - 全セグメントが同じ量だけずれている
   - 原因: 動画の開始位置が変わった、SRT変換時のオフセットミス
   - 対応: 全セグメントに同じオフセットを適用

2. **個別のずれ** - 特定のセグメントだけずれている
   - 原因: 手動編集ミス、SRT変換のバグ
   - 対応: 該当セグメントのみ修正

3. **累積ずれ** - 後ろに行くほどずれが大きくなる
   - 原因: フレームレート変換ミス
   - 対応: フレームレートを確認、再変換

---

## 修正ルール

### ⚠️ 最重要: 慎重に修正する

音声同期の修正は**非常に慎重に**行う必要があります。

1. **必ず元のSRTファイルを参照**
   - SRTのタイムスタンプが正解
   - 勝手にタイミングを変えない

2. **修正前に必ずユーザーに確認**

3. **一括修正は危険**
   - 1つずつ確認しながら修正
   - 全体オフセットの場合のみ一括修正を検討

### 修正可能なケース

- ✅ SRTファイルが存在し、タイムスタンプが確認できる
- ✅ ユーザーが明示的に修正を許可した
- ✅ ずれの原因が明確

### 修正禁止のケース

- ❌ SRTファイルがない（正解データがない）
- ❌ ユーザーの確認なし
- ❌ ずれの原因が不明

## 計算式

### SRTタイムスタンプ → フレーム変換

```typescript
// settings.json から fps を取得
const fps = 25;

const srtToFrame = (timestamp: string) => {
  // "HH:MM:SS,mmm"
  const [time, ms] = timestamp.split(',');
  const [h, m, s] = time.split(':').map(Number);
  const seconds = h * 3600 + m * 60 + s + parseInt(ms) / 1000;
  return Math.floor(seconds * fps);
};
```

### ずれの計算

```
ずれ = subtitleDataのstartFrame - SRTから計算したstartFrame
```

- 正の値: テロップが遅れている
- 負の値: テロップが早い
